Agentes com autonomia.

Deixar agentes de IA soltos no terminal sem limites é receita para incidentes. O AIOSON classifica toda operação em 3 tiers estritos de permissão: tarefas seguras rodam sem atrito, alterações locais são notificadas e comandos destrutivos são bloqueados na raiz.

01 / Governança

Os 3 Tiers de Autonomia do AIOSON.

Cada comando executado por um agente passa por uma esteira de classificação antes de tocar no sistema operacional:

T1
Silent · Sem atrito

Operações Seguras e Leitura

Leituras de arquivos locais, validação de regras, buscas no SQLite, inspeção de git status e verificação de integridade. Executam de forma silenciosa e instantânea.

Exemplos T1: • aioson context:validate • aioson feature:current • aioson memory:search • aioson op:list
T2
Notified · Reversível

Escritas Locais e Memória

Geração de código em arquivos permitidos pelo plano, gravação de aprendizados no INDEX.md, criação de branches temporárias de worker e registros de eventos.

Exemplos T2: • aioson op:capture • aioson memory:reflect • aioson plan:bind • Escrita em .aioson/features/
T3
Blocking · Hard-Rejected

Ações Destrutivas e Externas

Publicação de pacotes no npm, push em branches de produção no git remoto, remoção de bancos de dados ou execução de comandos com privilégio elevado. Bloqueados por padrão.

Exemplos T3: • npm publish • git push --force origin main • Fechamento sem aprovação de QA • Acesso a redes não autorizadas
Hard-Reject: A Linha Vermelha do Autopilot

Mesmo quando uma feature roda no modo --auto (Autopilot), ela nunca publica código em produção nem deleta arquivos fora do escopo. O Autopilot encerra apenas até a homologação final do @qa sob autorização explícita de uma política closure-policy.json.

02 / Ambientes

Harnesses: rodando com qualquer IA e editor.

O AIOSON é agnóstico ao cliente de IA. Ele compartilha o mesmo estado de memória e permissões em múltiplos harnesses suportados:

CL

Claude Code

Suporte completo a comandos em barra (/briefing, /product, /dev) e chamadas diretas com leitura de contexto.

.claude/ · full integration
CX

OpenAI Codex

Execução rápida de tarefas em lote e geração de testes unitários com respeito aos contratos contratuais.

codex-engine · sandbox local
OC

OpenCode

Ambiente de código aberto para desenvolvedores que utilizam modelos locais via Ollama ou vLLM sem vazamento de dados.

opencode.json · offline first
CR

Cursor Runner SDK

Novo em v1.67.0: Workers headless dedicados executando ondas paralelas com alta velocidade e baixo overhead.

.cursor/ · live multi-worker

03 / Flexibilidade

Perfis de autonomia pré-configurados.

Você pode definir o nível de intervenção humana desejado para cada repositório em .aioson/config.md:

creator

Modo Criação Acompanhada

Ideal para novos projetos onde você quer validar cada decisão arquitetural e visual antes de continuar.

  • Pausa obrigatória após cada agente
  • Aprovação humana em todos os portões
  • Feedback visual obrigatório no Gate B
developer

Modo Desenvolvimento Ágil

O equilíbrio perfeito: automação fluida de tarefas rotineiras com paradas apenas em decisões reais de escopo.

  • Dev implementa ondas de forma contínua
  • QA executa verificações automáticas
  • Pausa apenas se houver conflito ou dúvida
team

Modo Corporativo & Squad

Configuração para equipes com múltiplos desenvolvedores compartilhando a mesma base de código.

  • Travas de colisão de arquivos ativas
  • Auditoria de conformidade de Squad Layer 6
  • Logs detalhados de telemetria no SQLite

04 / Defesa ativa

O agente @pentester e varredura de segurança.

Qualidade não é apenas ausência de bugs visuais: é garantir que o código novo não abra brechas de segurança. O agente @pentester analisa a superfície de ataque da feature:

Superfície Auditada O que é Verificado Comando do CLI
Vazamento de Segredos Busca por chaves de API, senhas ou tokens gravados em arquivos de código. aioson security:scan --secrets
Injeção & Sanitização Conferência de parâmetros de consulta SQL, comandos de shell e inputs HTML. aioson security:scan --injection
Dependências Vulneráveis Verificação de CVEs conhecidos nos pacotes importados pelo projeto. aioson security:scan --deps
Auditoria do Pentester Análise cética executada pelo agente especializado antes do Gate D. aioson security:audit
cli · tentativa de comando bloqueado (hard-reject)
# Executar varredura completa de segurança no projeto $ aioson security:scan . secrets 0 exposed credentials injections 0 unescaped query parameters veredicto PASS · conformidade com políticas corporativas # Exemplo de agente tentando ação de Tier 3 sem permissão $ npm publish ✖ HARD-REJECT (Tier 3): Ação de publicação bloqueada pelo runtime de autonomia. > Motivo: Publicação externa exige execução manual por um operador humano autenticado.
